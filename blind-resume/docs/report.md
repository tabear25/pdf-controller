# 最終報告（M1〜M5）

## 結論

- 依頼の第 3 章のうち、必須の機能（3-1）と、あるとよい機能（3-2）をすべて実装しました。第 2 章の前提（ブラウザの中で完結する、画像にして書き出す、入力の PDF を信頼しない、最後は人が判断する）は変えていません。
- テストは、単体テスト 98 件と、E2E テスト 56 件 × 2 方式（file:// と、ローカルの静的サーバー）の 112 件が、すべて合格しています。GitHub Actions でも、Linux、Windows（Chrome、Edge）、macOS（Chrome）で合格しています。
- 残っている作業は、利用者側の 3 つです。Vercel への公開、GitHub と Vercel の 2 段階認証、実物の PDF を社用 PC で試すこと（下の「残っている課題」）。

## 作ったもの

| 機能 | 内容 |
|---|---|
| 読み込みと表示 | ファイルの選択とドラッグ＆ドロップ。日本語（cMap 同梱、埋め込みのないフォントは PC のフォント）、スキャン PDF（CCITT、JBIG2、JPEG、JPEG 2000）、回転、CropBox。パスワード付きの PDF（パスワードは保存しない）。別のファイルを開くか「クリア」で、前のデータを解放する |
| 塗る範囲 | ドラッグで作成、移動、8 方向のつまみで大きさの変更、Delete で削除、元に戻す・やり直す（Ctrl+Z・⌘Z など）。座標は表示の向きで倍率 1 のポイント。全ページの同じ位置への適用（大きさや向きが違うページは除き、ページ番号を表示） |
| 同じ文字列の候補 | 範囲の中の文字を検索語の欄に入れ、文書全体から探す。直接入力でも探せる。全角と半角、空白、英字の大小、ひらがなとカタカナ、ハイフン類の違いを区別しない。字間の空いた氏名にも一致する。候補は「未確認」として示し、1 件ずつかまとめて「塗る」「塗らない」を選ぶ。塗る範囲に覆われている候補は除く。文字の情報がない PDF では、その旨を表示する |
| 自動の候補（M5） | 開いたときに、メールアドレス、電話番号（全角、各種ハイフン、括弧、+81）、郵便番号、URL、年齢を探して候補にする。日付・年号は既定では探さない |
| 表示（M5） | 拡大、縮小、幅に合わせる（範囲の座標は変わらない） |
| ページの除外（M5） | ページごとに「このページを書き出す」を外せる（元に戻せる） |
| 書き出し | 150・200・300dpi（既定 200）。ブラウザの描画の上限に近いページは解像度を自動で下げて表示する。画面と同じ描画の設定で画像にし、画素の境界まで外側に広げて不透明な黒で塗る。表示の向きと大きさのページで、文書情報のない画像だけの PDF を作る。ファイル名は `blind_resume_YYYYMMDD_HHMM.pdf`（変更可） |
| 書き出し後の検査 | 出力を読み直し、構造（ページと画像だけ）、文字 0 件、注釈・添付ファイル・しおり・スクリプト・フォームなし、元の文書情報なし、ページ数・大きさ・向き、塗った範囲が黒（縁から 2px 内側）を確かめる。すべて合格したときだけダウンロードできる |
| 確認画面 | 検査の結果と検査の範囲の説明、元の PDF と出力の並列表示、漏れやすい箇所のチェックリスト（`src/config/checklist.ts` の 1 か所で定義）、確認のチェック。進み具合と出力のサイズを表示する |
| 安全の仕組み | meta の CSP（スクリプトはハッシュだけ、`connect-src 'none'` など）、Trusted Types、すべてを 1 ファイルに同梱、保存系の API を使わない、タイトルと URL の固定。`vercel.json` で同じ CSP をヘッダーでも返す |

成果物は、`dist/index.html`（約 4.1MB、file:// でもサーバーからでも動く 1 ファイル）、`dist/THIRD_PARTY_LICENSES.txt`（アプリの画面からも見られる）、`dist/index.html.sha256`、`vercel.json`、ソースとテスト、README、`docs/` の設計文書です。

## 使い方

[README](../README.md) の「使い方」にまとめています。流れは「開く → 自動の候補を確かめる → ドラッグで囲む → 同じ文字列を探す → 書き出す → 目で確かめてダウンロード」です。

公開は、Vercel で `tabear25/pdf-controller` を取り込み、Root Directory に `blind-resume` を指定するだけです（ビルドはしない設定が `vercel.json` に入っています）。手順は README の「公開の手順」にあります。

## 既知の限界

1. **候補の位置は見積もり**：PDF.js は文字のまとまりごとの位置しか返しません。全角の文字と等幅の半角（MS ゴシックなど）は正確に求まりますが、プロポーショナルの欧文の中や、かなの幅が 1 字分でないフォント（MS P ゴシックなど）ではずれることがあります。枠は余裕をとって広げ、人が確かめる前提にしています（[design.md](design.md)）。
2. **黒の検査は塗り漏れを確かめない**：自動の検査が確かめるのは書き出しの仕組みです。伏せるべき箇所を伏せたかどうか、写真の中の文字、スキャン PDF の氏名は、人が確かめます。黒の判定は書き出しと同じ座標の変換を使うので、変換そのものの誤りは、確認画面の並列表示と、開発時の独立した検査で見つけます。
3. **ブラウザの版**：PDF.js 6.x の要件で、Chrome 145 以降（2026 年 2 月以降の版）が必要です。古い版では、その旨を表示します。
4. **アプリの外の脅威**：ブラウザの拡張機能、ブラウザ本体の脆弱性、配信物のすり替え（アカウントの乗っ取り）は、アプリでは防げません。シークレット ウィンドウでの利用と、2 段階認証、SHA-256 の照合で備えます。
5. **メモリ**：閉じた PDF のデータが実際にメモリから消える時期は、ブラウザが決めます。
6. **出力**：画像だけの PDF なので、文字の選択や検索はできず、元より大きくなることがあります。

## 依頼から変えた点、足した点

| # | 依頼 | 実装 | 理由 |
|---|---|---|---|
| 1 | `isEvalSupported` を false にする | 設定していない | PDF.js 6.x でオプションごと廃止され、PDF から JavaScript を組み立てて実行する経路も取り除かれた。CSP（`'unsafe-eval'` なし）と Trusted Types で、eval の類がブラウザの仕組みとして止まることを E2E で確かめている |
| 2 | `'wasm-unsafe-eval'` が必要なら報告する | 許可した（承認済み） | スキャン PDF の CCITT・JBIG2・JPEG 2000 の復号に要る。JS 版の代替は動的な import を使うため、1 ファイル・通信遮断の構成では使えない（[security.md](security.md)） |
| 3 | blob: や data: は必要な範囲で | blob: を `worker-src` にだけ入れた。PDF.js の Worker をビルド時に classic 形式へ変換し、blob: から起動する | file:// では、blob: から module 形式の Worker を起動できない。`script-src` に blob: を入れると、スクリプトを組み立てて実行できてしまう |
| 4 | （追加）Trusted Types | 導入した | HTML の注入と、文字列からのスクリプト生成を、ブラウザの仕組みとして塞ぐ |
| 5 | 同梱するフォント | Symbol と ZapfDingbats 用の Foxit フォントだけ | PDF.js が同梱する Liberation Sans は GPLv2（フォント例外つき）で、「許容的なライセンスに限る」に合わない。ほかの標準フォントは PC のフォントで描く |
| 6 | 出力の PDF の作成（pdf-lib か jsPDF） | pdf-lib | 文書情報（Producer など）を書かない設定ができる |
| 7 | 検索で全角・半角と空白の違いを区別しない | 英字の大小、ひらがなとカタカナ、ハイフン類の違いも区別しない | ふりがな、ローマ字、電話番号の取りこぼしを減らす。候補は人が確認するので、広めに拾うほうが安全 |
| 8 | 自動で検出する候補 | 開いたときに自動で探す（日付・年号以外） | 押し忘れによる見落としを防ぐ。結果は未確認の候補なので、塗るかどうかは人が決める |
| 9 | 候補の矩形を大きめにする | 余白に加えて、文字の位置の見積もりの誤差に応じた余裕をとる。同じ行の近い矩形は 1 つにまとめる | 全角と半角が混ざる行で、電話番号の枠が数字の端を覆わない例を E2E で見つけたため |
| 10 | （追加）出力の構造の許可リスト検査、JPEG のメタデータの除去 | 想定外のオブジェクトや項目があれば不合格にする。JPEG のカラープロファイルなどの区画を取り除く | 「入っていないもの」を個別に並べるより取りこぼしがない。Chrome の JPEG にはカラープロファイル（APP2）が入る |
| 11 | （追加）確認画面の確認チェック | 1 つのチェックで、ダウンロードを有効にする | 自動の検査は塗り漏れを確かめられない。チェックリストの全項目にチェックを求めると、形骸化しやすい |
| 12 | （追加）タイトルと URL の固定 | 固定した | ブラウザの履歴に、候補者の名前やファイル名が残らないようにする |
| 13 | （追加）ルートの `.gitignore` | `tests/fixtures/pdf/` 以外の PDF を除外 | 既存の Tkinter アプリの出力などがコミットされないようにする |
| 14 | 公開の方法 | ホスト側でビルドせず、コミットした `dist/` をそのまま配る。SHA-256 を公開する | 配信物を、レビュー済みのコミットと同じものにする |
| 15 | （技術の選択）UI | フレームワークを使わず、TypeScript と `createElement` の小さな関数で作った | 同梱物と攻撃面を小さくする。PDF 由来の文字を HTML として扱う口を作らない |
| 16 | （開発の手順） | 依存の追加は npm 11 で行い、ビルド用のツールは公開から 2 週間以上たった版を選んだ | npm 10 の `npm install` は依存の解決に失敗する。出たばかりの版の不具合や乗っ取りの影響を避ける |
| 17 | （テストのデータ） | ダミー PDF 03 の字間の指定が後の行に漏れていたのを直し、半角の濁点が離れる行を足した | 検索の取りこぼしを正しく試すため |

## 残っている課題

1. **公開（利用者の作業）**：Vercel でプロジェクトを作り、Root Directory に `blind-resume` を指定します。GitHub と Vercel の 2 段階認証、main ブランチの保護も設定してください。公開後に、配信された `index.html` の SHA-256 を `dist/index.html.sha256` と照合します。
2. **実物の PDF での確認（利用者の作業）**：社用 PC の Chrome で、実物の PDF を数件試してください。とくに見てほしいのは、候補の枠が文字を覆っているか（英数字の多い行）、書き出しの見た目が元と同じか、`chrome://version` の版が 145 以上か、社内のネットワークで vercel.app が開けるか、です。問題があれば、PDF そのものではなく、症状と画面の様子を教えてください（実物はリポジトリに入れません）。
3. **PR のレビューとマージ**：PR #2 は下書きのままです。確認のうえで main に取り込むと、Vercel の本番に反映されます。
4. **PDF.js の更新**：6.x は毎月更新されます。脆弱性の修正が出たときは、[design.md](design.md) の「PDF.js を更新するとき」の手順で更新し、E2E テストで確かめます。
5. **改善の余地（今回は入れていない）**：プロポーショナルのフォントでの候補の位置は、フォントの文字幅の情報を PDF.js から取り出せば正確にできますが、仕組みが大きくなるので見送りました。実物で枠のずれが目立つ場合に検討します。OCR、テンプレート、一括処理は、依頼の対象外です。
