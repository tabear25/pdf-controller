# 設計メモ

コードにはインラインコメントを書かない方針なので、設計の判断と注意点をここにまとめます。安全性に関わる判断は [security.md](security.md) にあります。

## 全体の構成

- `src/pdf/`：PDF.js の設定と、文書の開閉（Worker、同梱データ、描画設定）
- `src/ui/`：画面（DOM は `ui/dom.ts` の `h()` だけで組み立てる）
- `src/core/`：DOM に依存しない処理（座標、正規化、検索など。M2 以降）
- `src/export/`：画像化、黒塗り、組み立て、自動検査（M3 以降）
- `src/config/`：文言、チェックリスト、上限値などの設定
- `scripts/`：ビルドの補助（仮想モジュール、ビルド後の検査、静的サーバー）

## PDF.js の設定（`src/pdf/settings.ts`）

| 設定 | 値 | 理由 |
|---|---|---|
| Worker | PDF.js の `pdf.worker.min.mjs` を classic 形式に変換し、blob: から起動する | file:// では blob: から module 形式の Worker を起動できない（Chromium で確認）。変換は `export` 1 か所の削除と `import.meta.url` 2 か所の置換だけで、ビルド時に構文を検査する |
| `useWorkerFetch` | `false` | Worker に通信させない。cMap などは、メイン側の `BundledDataFactory` がメモリから渡す |
| `BinaryDataFactory` | `BundledDataFactory` | cMap、標準フォント、WASM を、ビルド時に埋め込んだ base64 から返す |
| `cMapUrl` / `wasmUrl` | `bundled:cmaps/` / `bundled:wasm/` | 実際には読みに行かない識別用の文字列。PDF.js が末尾の `/` を要求する |
| `standardFontDataUrl` | 指定しない | 指定すると、PDF.js が代わりのフォントの指定に `url()` を混ぜ、CSP の違反が出る。指定しなくても、Symbol と ZapfDingbats は `BundledDataFactory` から渡る |
| `useSystemFonts` | `true` | 埋め込みのない欧文の標準フォント（Helvetica など）は、PC のフォント（Windows なら Arial など）で描く |
| `useWasm` | `true` | CCITT・JBIG2・JPEG 2000 の復号に要る（CSP に `'wasm-unsafe-eval'` が必要） |
| `enableXfa` | `false` | XFA フォームを HTML として描かない |
| `disableWorkerRendering` | `true` | 描画はメインスレッドの canvas で行う（書き出しで画素を扱うため） |

同梱する標準フォントは、Symbol と ZapfDingbats 用の Foxit フォント（BSD 系）だけです。PDF.js が同梱する Liberation Sans は GPLv2（フォント例外つき）で、依頼の「許容的なライセンスのものに限る」に合わないため、入れていません。`useSystemFonts: true` の設定では、ほかの標準フォントは PC のフォントで描かれるので、Liberation と Foxit の残りは使われません。

ICC プロファイル（qcms）と JavaScript の実行環境（QuickJS）は入れていません。ICC を使わない場合、PDF.js は代わりの色空間で描きます。

## 描画の設定（画面と書き出しで共通）

`RENDER_SETTINGS` を 1 か所で定義し、画面の描画と書き出しの両方で使います。

- `intent: "display"`
- `annotationMode: AnnotationMode.ENABLE`：注釈とフォームの見た目を canvas に描く。コメントの本文のように画面に描かれないものは、書き出しにも出ない
- `background: rgb(255,255,255)`：書き出しの画像が透明にならないようにする

注釈とテキストの層は DOM として作りません。PDF の中のリンクも、画面には作りません。

## 座標の扱い（M2）

- 塗る範囲は、ページごとに「表示の向きで、倍率 1 のときのポイント」で持つ（原点は表示の左上）。これは PDF.js の `getViewport({ scale: 1 })` の座標系と同じで、回転（/Rotate）、CropBox のずれ、UserUnit を反映した後の座標である。
- 画面の CSS ピクセルへは「1 ポイントあたりの CSS ピクセル」を掛けるだけ、書き出しの画素へは「dpi ÷ 72」を掛けるだけで変換できる。倍率を変えても、保存した座標は変わらない。
- PDF の座標（文字の位置など）から表示の座標への変換は、`src/core/geometry.ts` の `displayTransform()` で行う。開いたページごとに PDF.js の viewport の変換行列と照合し（`PageModel.transformVerified`）、一致しないページでは文字の候補を出さない。
- 書き出しで塗る画素は、`toPixelBox()` で外側の画素の境界まで広げる（左上は切り捨て、右下は切り上げ）。

単体テスト（`tests/unit/geometry.test.ts`）では、`displayTransform()` を次の 2 つと突き合わせている。

1. テスト側に別に書いた変換式（`tests/e2e/geometry.ts`。回転 0・90・180・270 と、負の値も含む CropBox のずれ）
2. ダミー PDF（回転、CropBox、原点が負のページ）を実際に PDF.js で開いたときの viewport

## 範囲の編集（M2）

- 状態は `src/core/editor.ts` の `EditorStore` が持ち、操作の履歴（元に戻す・やり直す）は `History` で管理する。ドラッグ中の位置は履歴に積まず、離したときに 1 回分として積む。
- 「全ページの同じ位置に適用」は、表示の向きでの幅と高さが 0.5pt 以内で一致するページにだけ写す。向きや大きさが違うページは除外し、ページ番号を表示する。同じ範囲がすでにあるページには重ねない。適用は 1 回の操作として元に戻せる。
- 操作：ドラッグで作成、範囲の中をドラッグで移動、角と辺のつまみで大きさの変更、Delete・Backspace で削除、矢印キーで 1pt（Shift で 10pt）移動、Esc で選択の解除とドラッグの取り消し、Ctrl+Z・⌘Z で元に戻す、Ctrl+Y・Ctrl+Shift+Z・⌘⇧Z でやり直す。

## 書き出し（M3、`src/export/`）

1. **解像度を決める**（`core/export-plan.ts`）：指定の dpi（150・200・300、既定 200）でページの画素数を計算し、4,000 万画素か、1 辺 16,384px を超える場合は dpi を下げる。下げたページは確認画面に表示する。
2. **描画して塗る**（`rasterize.ts`）：画面と同じ `RENDER_SETTINGS` で canvas に描き、塗る範囲を `toPixelBox()` で外側の画素の境界まで広げて、不透明な黒（#000000）で塗る。塗った直後に、範囲の全画素が (0,0,0) かを確かめ、違えば書き出しを止める。
3. **JPEG にする**：品質 0.9。Chrome の JPEG にはカラープロファイル（APP2）が入るので、`stripJpegMetadata()` で JFIF（APP0）と、量子化表・ハフマン表・フレームなど復号に要る部分だけを残す（APP1〜APP15、COM は捨てる）。
4. **組み立てる**（`assemble.ts`）：pdf-lib で 1 ページ 1 画像の PDF を作る。`updateMetadata: false` で文書情報を書かず、pdf-lib が付ける空の `/Annots` と空の `/Font`・`/ExtGState` も消す。ページの大きさは元のページの表示の大きさ（ポイント）、回転なし。

## 書き出し後の自動検査（`verify.ts`）

出力を読み直して、次を確かめる。1 つでも不合格なら、ダウンロードできない。

| 検査 | 方法 |
|---|---|
| 中身がページと画像だけ | pdf-lib で全オブジェクトを列挙し、許可リスト（Catalog、Pages、Page、画像、描画命令のストリーム）と、それぞれの許可された項目だけでできているかを確かめる。描画命令は `q`・`Q`・`cm`・`Do` だけ。画像は JPEG で、メタデータの区画がないこと |
| ページ数、大きさ、向き | PDF.js で読み直し、元の表示の大きさ（0.5pt 以内）と回転なしを確かめる |
| テキスト 0 件 | 全ページの `getTextContent()` |
| 注釈、添付ファイル、しおり、スクリプト、フォーム | `getAnnotations()`、`getAttachments()`、`getOutline()`、`getJSActions()`、`getFieldObjects()` |
| 文書情報 | `getMetadata()` で、Title などの項目と XMP がないこと、元の PDF の文書情報の値が含まれていないこと |
| 塗った範囲が黒 | 出力を同じ解像度で描き直し、各範囲を縁から 2px 内側で調べる。全画素の RGB の最大値が 96 以下、平均が 16 以下なら合格 |

黒の判定にしきい値があるのは、JPEG の圧縮で、黒の縁に近い画素がわずかに明るくなるためです。塗り忘れや位置のずれがあれば、白や文字の画素が入るので、このしきい値で見分けられます。

**この検査で分からないこと**：黒の判定は、書き出しと同じ座標の変換で範囲を求めます。そのため、変換そのものに誤りがあると、利用者が画面で見た位置と違う場所を塗っていても合格してしまいます。この誤りは、確認画面の並列プレビュー（人の目）と、E2E テストの独立した検査（下記）で見つけます。

## 確認画面

- 自動検査の結果、検査の範囲の説明、解像度を下げたページ、ページ数・ファイルサイズ・解像度を表示する。
- 元の PDF（塗る範囲を赤い点線で表示）と、書き出した PDF を並べて表示する。
- 漏れやすい箇所のチェックリスト（`src/config/checklist.ts`）と、「プレビューを見て確かめた」のチェックを置く。ダウンロードできるのは、自動検査にすべて合格し、このチェックが入ったときだけ。
- ファイル名の既定値は `blind_resume_YYYYMMDD_HHMM.pdf`。編集でき、使えない文字（`\ / : * ? " < > |` と制御文字）は取り除く。

## E2E テストでの独立した検査（`tests/tools/verify_output.py`）

アプリとは別の実装（pikepdf、pypdf、poppler）で、書き出した PDF を調べます。

- 全オブジェクトと、画像を除いたファイル全体から、ダミーの氏名などの文字列を探す（UTF-8、UTF-16、16 進、Shift_JIS、EUC-JP、名前の `#xx` 表記）。同じ検査を入力の PDF にもかけ、入力側では見つかることを確かめる（検査そのものが働いていることの確認）。
- 構造（カタログ、ページ、リソース、画像の項目）、JPEG のメタデータ、取り出せる文字を調べる。
- poppler で描き直し、ダミー PDF を作ったときに記録した氏名などの位置（PDF の座標を、テスト側の独立した計算で表示の座標に直したもの）が、すべて黒になっているかを確かめる。

## 同じ文字列の候補（M4）

### 文字の情報と位置

- 開いたあと、全ページの `getTextContent()` を読み、ページごとに索引（`src/core/text-index.ts`）を作る。座標の変換を確かめられなかったページ（`transformVerified` が false）は対象から外し、その旨を表示する。
- PDF.js が返すのは「断片（item）」ごとの位置（変換行列と幅）で、1 文字ずつの位置はない。断片の両端の位置は正確なので、断片の中の文字の位置を、次の順で見積もる（`layoutItem()`）。断片の高さは、フォントの ascent と descent から求める（ない場合は 0.8 と 0.2）。
  1. 文字を「全角（漢字、かな、全角英数字・記号）」と「半角（英数字、空白、半角カナなど）」に分ける。日本語のフォントでは、全角の文字の幅はほぼ例外なく 1 字分（1em）である。
  2. 断片の幅（em）から全角の字数を引いた残りを、半角の文字の幅の合計とみなす。半角 1 文字あたりがちょうど 0.5em なら、等幅の半角（MS ゴシック・MS 明朝・IPA ゴシックなど）とみなして、すべて 0.5em で割り付ける。この場合、位置は正確になる。
  3. そうでなければ（プロポーショナルの欧文など）、半角の文字に目安の比（英数 0.55、空白 0.3、半角カナ 0.5）で残りの幅を配る。字間（Tc）が大きい場合などに極端な値にならないよう、目安からの補正は 0.5〜1.5 倍にとどめる。
  4. 3 の場合、半角の文字の幅は推定でしかない。断片の端から数えた半角の字数（前後の少ないほう）× 0.06em を、その位置の「余裕」として、候補の矩形（覆われているかの判定に使う矩形を含む）を文字の並ぶ向きに広げる。断片の端に近い位置ほど誤差が小さく、半角の文字に挟まれた位置ほど大きいことに合わせている。
- 候補の矩形は、さらに上下左右に「2pt か文字の高さの 20%（大きいほう）」を広げる。同じ行で近い矩形（均等割り付けで離れた文字など）は 1 つにまとめる。
- この見積もりは、全角の文字が 1em でないフォント（MS P ゴシックなどのプロポーショナルのかな）や、断片の中で字間が変わる場合にはずれる。候補の矩形は提案であり、塗る前に人が位置を確かめる前提である。
- ページの外にある文字（CropBox の外など）は候補にしない。

### 検索の正規化（`src/core/normalize.ts`）

- 文字を「基底の文字＋後に続く結合文字（濁点・半濁点・異体字セレクタなど）」のまとまりに分け、まとまりごとに NFKC、英字の小文字化、カタカナからひらがなへの変換、ハイフン類（‐ – — ― − ー ─ ━ － など）の「-」への統一をかける。空白は取り除く。
- PDF.js は、字間の空いた文字の間に空白を入れることがある。半角の濁点（ﾞ）が空白をはさんで離れていても、直前の文字にまとめる。
- 正規化した文字列の 1 文字ごとに、元の文字の範囲（開始と終了）を持つ。「㈱」→「(株)」のように文字数が増える場合も、「ｶﾞ」→「が」のように減る場合も、一致した範囲を元の文字の範囲に正しく戻せる。
- 断片の境目も、空白と同じように扱う。均等割り付けで別々の断片になった氏名も一致する。

### 候補の扱い

- 検索の結果は「未確認」の候補として加える。同じ位置の候補は重ねて加えない。すでに塗る範囲に覆われている候補（広げる前の文字の矩形で判定）は、未確認の一覧から除く。
- 「塗る」は候補の矩形を塗る範囲に加え、「塗らない」は候補を閉じる。1 件ずつでも、まとめてでも選べ、元に戻せる。
- 範囲をドラッグで作ると、範囲の中に中心がある文字を読み取り、検索語の欄に入れる。利用者が欄を書き換えたあとは、上書きしない。
- 書き出しの前に未確認の候補が残っていれば、一覧を示して「戻って確かめる」「すべて塗らずに進む」「すべて塗ってから進む」から選んでもらう。

## 3-2 の項目（M5）

### 自動で見つける候補（`src/core/detectors.ts`）

- 文字の索引（空白を 1 つに詰め、NFKC などで正規化した文字列）に正規表現をかけ、見つかった範囲を、検索と同じ仕組みで「未確認」の候補にする。全角の数字やハイフン類は正規化で半角にそろうので、同じ式で拾える。候補の一覧には、元の表記（全角のままなど）を表示する。
- 対象と既定：メールアドレス、電話番号、郵便番号、URL、年齢は既定で有効。日付・年号は、学歴・職歴の年月まで拾って候補が多くなるので、既定では無効（依頼のとおり）。
- 電話番号は、数字・空白・ハイフン・括弧・「+」の並びを走査し、「0 で始まる 10〜11 桁」か「+81 で始まる 9〜10 桁（先頭の 0 を除く）」になる区切りのうち、最も長いものを取る。括弧の釣り合わない並びや、空白が 2 つ続く並びは取らない。
- PDF を開いて文字の情報を読み終えたら、有効な種類で 1 回探す。この結果は「開いた直後の状態」として履歴に積む（`seedCandidates`）。そのため、開いた直後は「元に戻す」が押せず、元に戻しても自動の候補は消えない。種類を変えて「この設定で探す」を押した結果は、通常の操作として元に戻せる。
- 検出は提案にすぎない。氏名、ふりがな、学校名、会社名などは対象にしていない（検索欄で探す）。

### 拡大と縮小

- 「−」「＋」は 25・50・75・100・125・150・200・300・400% の段階（100% は 1pt＝96/72 CSS ピクセル）を移り、「幅に合わせる」で表示欄の幅に合わせる。倍率は表示だけに効き、範囲の座標（倍率 1 のポイント）は変わらない。

### ページ単位で出力から外す

- 各ページの上の「このページを書き出す」のチェックを外すと、そのページを出力に入れない。外したページは薄く表示し、斜線をかける。外す・戻すは、元に戻せる操作として履歴に積む。
- 書き出しは、残したページだけを順に画像にする。外したページにある未確認の候補は、書き出し前の確認の対象にしない。自動検査のページ数は「残したページの数」と照合し、確認画面に「N ページ（M ページは書き出さない）」と表示する。すべてのページを外したときは、書き出さずに知らせる。

### パスワード、進み具合、出力のサイズ

- パスワード付きの PDF は、開くときに入力を求める（M1 から）。パスワードは PDF.js に渡したらすぐ入力欄から消し、保存しない。
- 書き出しの間は、段階（ページを画像にして塗る、PDF を組み立てる、書き出した PDF を検査する）と、何ページ目かを進み具合のバーと一緒に表示し、中止できる。確認画面に出力のファイルサイズを表示する。

## ページの表示（`src/ui/viewer.ts`）

- 各ページの大きさは、`getViewport({ scale: 1 })` の幅と高さ（回転と CropBox を反映した、表示の向きでのポイント）を基準にする。
- 画面での倍率は「1 ポイントあたりの CSS ピクセル」で持つ。canvas は、その倍率に `devicePixelRatio` を掛けて描く。1 ページの canvas が 1,677 万画素を超える場合は、解像度を下げる。
- 見えている付近（上下 1,200px）のページだけを描き、離れたページの canvas は解放する。

## 文書の開閉（`src/pdf/document.ts`）

- 文書ごとに Worker を新しく作り、閉じるときに `loadingTask.destroy()` のあとで Worker を終了する（6.x の `PDFDocumentProxy` には `destroy()` がない）。
- 読み込んだバイト列は Worker に移されるので、メイン側に元の PDF のコピーは残らない。
- パスワードは、入力欄の値を PDF.js に渡したらすぐ消す。保存しない。

## ビルド（`scripts/`）

- `build-plugin.mjs`：仮想モジュールを提供する。
  - `virtual:pdfjs-worker-source`：classic 形式に変換した Worker のソース
  - `virtual:pdfjs-data`：cMap（全 168 種）、標準フォント（2 種）、WASM（2 種）の base64
  - `virtual:licenses`：第三者ライセンスの本文
  - `virtual:build-info`：版の表示用
  - あわせて、実際に同梱されたパッケージとライセンス一覧の対応を検査し、ずれていればビルドを止める。
- `postbuild.mjs`：`dist/index.html` を検査して仕上げる。
  - インラインのスクリプトが 1 個、style が 1 個以下であること、`link` 要素・`src`/`href` 属性・インラインのイベント属性・`style` 属性がないこと
  - innerHTML、eval、new Function、保存系の API などが成果物にないこと
  - URL の文字列が許可リストの中だけであること（名前空間やライセンス条文など、通信しないもの）
  - スクリプトと style の SHA-256 を計算して CSP の meta タグに入れ、同じ CSP（と `frame-ancestors`）を `vercel.json` のヘッダーにも書く
  - `dist/THIRD_PARTY_LICENSES.txt` と `dist/index.html.sha256` を書き出す

ビルドの結果は決定的です（日時などを埋め込まない）。CI では、コミットされた `dist/` と `vercel.json` がビルド結果と一致するかを確かめます。

## PDF.js を更新するとき

1. `package.json` の `pdfjs-dist` を新しい版に固定し、`npm install` する（npm 10 の `npm install` には依存解決の不具合があるため、`npx npm@11 install` を使う。`npm ci` は npm 10 でも動く）。
2. `npm run build` が通るか確かめる。Worker の変換が想定どおりでない場合（`export` の形や `import.meta.url` の数が変わった場合）は、ビルドが止まる。変換の内容を確認してから、`scripts/build-plugin.mjs` の想定を直す。
3. `npm test` と `npm run test:e2e` を通す。特に、スキャン PDF（CCITT、JPEG 2000）とフォント非埋め込みの PDF を確かめる。
4. URL の許可リストに新しい文字列が出た場合は、通信に使われないことを確認してから足す。

## ダミー PDF（`tests/fixtures/`）

- `generate.py` で作る（reportlab、pypdf、pikepdf、Pillow、img2pdf）。必要な Python パッケージは `tests/requirements.txt`、日本語フォントは IPA ゴシック（`FIXTURE_FONT` で変更可）。
- 生成物は `tests/fixtures/pdf/` にコミットし、テストはそれを使う。生成し直しても同じバイト列になる。09（パスワード付き）は暗号化に乱数を使うため、すでにあれば作り直さない（`--force-encrypted` で作り直す）。
- `manifest.json` に、各ページの MediaBox、CropBox、回転、氏名などの位置（PDF の座標）を記録する。E2E テストは、この位置をテスト側の独立した計算で画面の座標に直し、アプリの描画と照合する。
